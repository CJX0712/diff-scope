两段文本差在哪，几乎所有工具都能告诉你。这个工具想说的是另一件事：**它是怎么找到那个答案的**。

Myers 差分算法的全过程 —— 每一轮的波前、每一条对角线的推进、最后那条最短编辑路径 —— 全部画在面板 3 的图上。

单个 HTML 文件，双击即用。零依赖、零构建、**完全离线**，文本只在本机内存里。

## 怎么用

下载 `index.html` → 双击打开 → 改任何一边都会自动重算。内置 4 个示例可以直接切。

## 核心：把 diff 变成一张地图上的最短路

设 A 有 N 个单元、B 有 M 个单元。画一张 (N+1)×(M+1) 的网格，点 `(x, y)` 表示「A 处理了 x 个、B 处理了 y 个」。从 `(0,0)` 走到 `(N,M)`：

| 走法 | 含义 | 代价 |
|---|---|---|
| 向右 `(x+1, y)` | 删掉 A 的这一单元 | 1 |
| 向上 `(x, y+1)` | 插入 B 的这一单元 | 1 |
| 斜着 `(x+1, y+1)` | 两边相等，**免费** | 0 |

于是「最短编辑脚本」就是这张图上**斜线最多、直线最少**的那条路。Myers 的洞见是：按「直线步数」`d` 一层一层往外搜，第一次够到终点就是最优解。

### 面板 3 在画什么

- **淡色折线**：每一轮 `d`，所有 `k` 对角线各自最远能推进到的位置连成的**波前**
- **粗线**：最终那条最短编辑路径 —— 青色是对角线（没变），红色是向右（删除），绿色是向上（新增）
- **滑块**：拖到第几轮，就看到第几轮为止的波前；拖到底才画出最终路径

令 `k = x − y`（第 k 条对角线）。算法维护 `V[k]`：走 d 步之后，在 k 这条对角线上最远能到达的 x。每轮对 `k = −d, −d+2, …, d` 各推进一步，然后沿对角线**能滑多远滑多远**（这就是 snake）。

复杂度 `O((N+M)·D)`，D 是编辑距离。文本越像，D 越小，跑得越快 —— 这正好是 diff 的常见情形。

### 为什么要保存每一轮的 V

算法往前推时只知道「最远能到哪」，不知道「怎么走到的」。所以要把每轮的 V 存下来，最后从终点**倒着**推回去：每一层看当时是从 `k−1` 还是 `k+1` 跳过来的，反推出是删还是插，再把斜着滑过的那段补成「相等」。

## 三种粒度

同一套算法，换掉「单元」的定义：

- **行** —— 常规 diff。被判为「一删一插」的相邻行还会**再跑一次词级 diff**，标出这一行里到底改了哪几个词
- **词** —— 中文逐字、英文按词、空白单独成段，适合看一句话改了哪几个字
- **字符** —— 最细粒度

## 整块移动

内容没改、只是换了位置的段落，普通 diff 会显示成「这里删了一块、那里加了一块」。这个工具会对所有删除块和插入块两两算 Jaccard 相似度，超过阈值的配对标记为**移动**（紫色 `⇄`），并在面板 5 列出「A 第几行 → B 第几行」。

## 自验证

面板 6 会把生成的 unified diff **重新打回 A**，再和 B 逐字节比。

这不是装饰。编辑脚本、补丁生成、补丁应用三处只要有一处写错，这里立刻就会红。开发时这个闭环抓到了一个真 bug：纯插入的 hunk 头 `@@ -a,0 @@` 在 unified diff 里的意思是「插在第 a 行**之后**」，插入点的 0 基下标就是 `a` 本身而不是 `a−1` —— 照 `a−1` 解析会让每个纯插入块都偏移一行。

## 局限

- **最坏情况是指数级的**。Myers 是 `O((N+M)·D)`，两端几乎毫无共同点时 D 会逼近 N+M，搜索空间爆炸。工具里有工作量上限，超限会明确报「差异过大」而不是假装算完了
- **回溯不是线性空间的**。用的是保存每轮 V 的经典做法，空间 `O(D²)`。对常规 diff 规模（几百行、D 几十）完全够用，但不适合几万行的超大文件
- 单元总数超过 4000 时不画编辑图（画了也是一团糊），但 diff 和补丁照常工作
- 移动检测用的是 Jaccard 阈值（默认 0.5）+ 贪心配对，不是最优匹配；短段落容易误判

## 本地验证

仓库不含测试框架，验证脚本在开发时是一次性的。改动后想在浏览器控制台里自查：

```js
const A = ['A','B','C','A','B','B','A'];
const B = ['C','B','A','B','A','C'];
const r = myers(A, B, (x, y) => x === y);
r.D                       // 5 —— 与 Myers 论文里的经典用例一致
applyScript(A, B, r.script)   // 必须逐元素等于 B
makePatch(A, B, r.script, 3, 'a', 'b')   // unified diff
applyPatch(A, makePatch(A, B, r.script, 3, 'a', 'b')).text === B.join('\n')  // true
```

`applyScript(A, B, script)` 是最强的自检：从 A 出发，删掉 `del`、补上 `ins`，必须逐单元还原出 B。顺序、配对、覆盖只要错一处就对不上。
